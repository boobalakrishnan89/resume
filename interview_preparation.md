```java
    assertEquals(res.statusCode(), 201);

@Test(priority = 2, dependsOnMethods = "createMember")

}
```

```yaml
# GitHub Actions Pipeline
name: QA Pipeline

on:
  pull_request:        # Trigger on PR
  schedule:
    - cron: '0 2 * * *'  # Nightly regression

jobs:
  smoke-tests:
    runs-on: ubuntu-latest

      - uses: actions/checkout@v3
      - name: Run Smoke Tests

          name: smoke-report

  regression-tests:
    needs: smoke-tests   # Only if smoke passes
    runs-on: ubuntu-latest
    strategy:
      matrix:
        browser: [chromium, firefox, webkit]

      - name: Run Regression

  api-tests:
    runs-on: ubuntu-latest
    steps:
      - name: Run API Tests
        run: mvn test -Dsuite=api

  notify:
    needs: [regression-tests, api-tests]
    steps:
      - name: Slack Notification
        run: curl -X POST $SLACK_WEBHOOK -d '{"text":"QA Pipeline Complete"}'
```

3. **User perspective** — "Would a user expect this behavior?"
4. **Data** — Check analytics — are users dropping off at this step?
5. **Escalate if needed** — Involve PM to clarify intent
6. **Document** — If it's truly "as designed," add to known behaviors/release notes
7. **Never make it personal** — Focus on the product, not the person

### Q32. You have 3 P1 bugs, 2 QA engineers are on leave, and the release is tomorrow. What do you do?
**Answer:**
1. **Prioritize** — Rank the 3 P1s by user impact and business criticality
2. **Communicate** — Immediately inform PM and Engineering lead about the situation
3. **Negotiate scope** — Can we release with 1 bug fixed + the other 2 behind feature flags?
4. **Hands-on** — I personally take on testing for the most critical fix
5. **Parallel work** — While dev fixes bugs, I prepare regression test environments
6. **Risk acceptance** — If 1 bug can't be fixed, document risk and get PM sign-off for delayed fix
7. **Never compromise silently** — Always escalate risks transparently

### Q33. How would you test a system that processes 10 million records per day?
**Answer:**
1. **Performance testing** — JMeter/k6 to simulate peak load
2. **Data generation** — Script to generate 10M+ realistic test records
3. **Database performance** — Monitor query execution times, index usage
4. **Memory profiling** — Check for memory leaks during sustained load
5. **Error handling** — What happens when 1000 records fail? Retry mechanism?
6. **Data integrity** — Sample validation on random records post-processing
7. **Monitoring** — Grafana dashboards for throughput, latency, error rates
8. **Chaos testing** — What happens when a downstream service goes down mid-processing?
